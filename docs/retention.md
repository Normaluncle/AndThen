# Consent expiry and maintenance

Public display grants made through the consent API now expire after 90 days by default. Optional `expires_at` may request a shorter deadline; later requested dates are capped at 90 days. Other purposes may also specify a future deadline. `expires_at` is returned in consent grants/lists/revocations.

Consent version is the replay key. Repeating an active version preserves its original grant/deadline and does not extend it. Changed deadlines, expired consent and revoked consent require a new version. Renewal retires the previous active version; a historical revoked version does not block a new explicit grant.

Public reads and listing check deadlines immediately. Legacy public consents with null expiry stop authorizing display 90 days after grant. The worker starts a `maintenance.consents` job and schedules another at the next ten-minute boundary. It updates expired consent status, withdraws notification metadata when public permission has ended, cancels expired model/private-purpose AI work, and switches active interviews to manual mode. All writes hold source locks and job fences; repeated sweeps cannot restore authorization.

Maintenance also closes running AI audit metadata whose job no longer has a valid running lease. It stores no late model output. A failed sweep uses the durable queue retry policy; restarting the worker seeds maintenance again. Public access expiry does not depend on a live maintenance worker.

Verified using isolated PostgreSQL tests in `tests/business/consent-expiry.test.ts`: default deadline, replay preservation, shorter period, immediate public denial, new-version renewal, legacy deadline handling, notification status, orphan audit cleanup, and next-job scheduling.

Private interviews and draft versions expire 30 days after their last operation (`updated_at`). Reads, writes, manual/AI drafting, validation and cached job-result reads enforce this deadline before maintenance runs. Reading does not extend retention. Expired interviews cannot be resumed. The ten-minute maintenance job deletes their messages/sessions, cancels their pending/running model jobs and removes related model audits, job results and owner response caches. A late model response fails the source/job fence or deadline check and cannot recreate deleted content. Automatic consent expiration does not refresh the interview retention clock.

Expired unpublished versions keep only their version number, historical hash and metadata; statements, edits, unresolved items and confirmations are removed. This prevents version-number reuse. Published versions keep public statements while their private statements and auxiliary fields are removed. `privatePurgedAt` means physical private-field cleanup has run; `contentPurgedAt` means all version text is gone. Before a sweep, the owner projection already omits expired private fields and returns `privateContentExpired: true`, without inventing a physical-cleanup timestamp. The historical `contentHash` remains the original confirmation receipt; it is not a hash of the reduced projection. Editing retained public text creates a new version with fresh author evidence and requires confirmation again.

Public access still independently requires valid public consent. Source snapshots are governed by source permission/deletion policy, not the interview/draft TTL. Explicit source deletion removes snapshots and all dependent content. This retention job does not claim automatic deletion of every source snapshot when a public grant expires.

Verified with real PostgreSQL in `tests/business/private-retention.test.ts` and the retention race in `tests/business/interview-ai.test.ts`: immediate denial, physical cleanup, public text preservation, untouched recent private content, job-cache denial, repeat safety, zero requests for expired inputs and rejected late replies. Physical cleanup requires a running worker and healthy database; the deadline read guards remain active during a worker outage. A bounded sweep processes up to 1,000 sources; monitor backlog/job failures before making timing guarantees to real participants.

Backup/restore scripts and their executed fixture evidence are documented in `docs/team-quickstart.md`. Managed backup rotation runs when `scripts/backup.ps1` is invoked; no automatic daily host schedule has been installed. External model retention depends on the independently configured provider; no remote deletion API is implemented. These limits must be resolved by a named operator before promising automatic end-to-end deletion deadlines to real participants.

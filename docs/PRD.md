# 01 产品定义与关键决策

## 1.1 一句话定义

【设计】“然后呢？”让读者对一条历史经历表达后续兴趣，让原作者自愿接受基于原文的 AI 回访，并将作者确认的后续与原回答关联保存、发布和重新阅读。

本期创造的内容关系是：**原问题 → 原回答／可核对的历史记录 → 原作者确认的后续。** 文内沿用“时间回访”作为机制名称。“时间验证”仅表示对照当时表述与后来回访，不代表平台已经独立核实人生结果，更不表示因果关系成立。

## 1.2 本期唯一核心闭环

**获准展示的真实旧回答 → 读者关注后续 → 判断是否适合回访 → 人工或已验证渠道邀请 → 核验原作者 → AI 动态采访 → 作者逐项确认 → 在本 Demo 发布后续 → 关注读者在 Demo 收到更新。**

没有知乎站内通知或发布 API，也可以完成这一闭环：通知和后续内容先在本 Demo 内实现，外部邀请由研究人员经合适渠道人工发送。不得把 Demo 内发布写成“已发布到知乎”，也不得把一次人工招募写成“大规模作者召回能力”。

## 1.3 八项产品决策

| 编号 | 决策 | 理由与边界 |
| --- | --- | --- |
| D01 | 读者关注进入主链，保留作者主动更新入口 | 读者需求与作者主动补充均有价值，不把其中一种设为唯一入口 |
| D02 | 不设高赞或满一年硬门槛 | 候选依据是存在可回访的事件／计划／判断；互动量只可作为辅助 |
| D03 | AI 做识别、采访、证据关联与整理 | 不替作者生成未提供的结果，不把自动评分包装成“最优时机” |
| D04 | 先做低敏感度成年人的学习、职业技能或项目经历 | 本期不做健康、重大创伤、未成年人等敏感回访 |
| D05 | 发布独立的后续记录并关联原回答 | 复制到知乎仅是可选出口，不代替 Demo 内完整内容对象 |
| D06 | 不依赖作者全量历史数据或站内推送才能运行 | 官方搜索／作者授权导入构成基础入口，未确认能力作为增强 |
| D07 | 未完待问、社交匹配、语音、经验 AI 均不进入 P0 | 48 小时优先完成一条可靠路径，避免把多项产品并列开发 |
| D08 | 用行为与证据评估，不承诺冠军或孵化 | 用户研究、API 联调、工程验收的结果分别报告 |

## 1.4 本期价值与非承诺

对读者，价值是可关注、可找回的真实后续；对作者，价值是低负担、可拒绝、可控制公开范围的补充经历入口；对平台，待验证价值是新增关联内容与后续互动。后两项是否带来留存、召回或收入提升，本期没有数据，不能预先宣布成立。

“必须长在知乎”在本文解释为**优先利用知乎历史问答、稳定账号关联和社区关系的适配性**，不声称其他社区技术上不能做，也不声称创意或通用算法具有排他性。

## 1.5 品牌与界面命名规则

本项目将「然后呢？」与「后来」分别固定在问与答两侧，不要求两个词机械统一。**「然后呢？」是读者发起继续了解的动作；「后来」是作者带回来的真实回应。**

| 使用位置 | 固定用词 | 说明 |
| --- | --- | --- |
| 正式项目名 | **然后呢？** | 品牌与产品机制名称，强调一段旧经历仍处于“未完、可继续追问”的状态 |
| 读者端主按钮 | **然后呢？** | 点击后建立“关注后续”关系；“关注后续”可作为内部动作名，不必作为主按钮文案 |
| 作者端内容名称 | **后来** | 作者完成回访后形成的内容对象，而不是新的问题 |
| 作者端主 CTA | **写下后来** | 进入回访／补充流程；如需更温和的邀请文案，使用“愿意讲讲后来发生了什么吗？” |
| 内容对象 | **一则「后来」** | 与原问题、原回答、回访时间和作者确认状态关联 |
| 对照展示 | **当时 / 后来** | 用于确认页、成品页和演示中的时间对照 |
| AI 行为 | **发起一次时间回访** | AI 负责理解旧材料、采访、追问、结构化与证据关联，不把“然后呢？”冷冰冰地抛给作者 |

命名理由：产品真正的起点是读者看到旧回答后自然产生“然后呢？”；它表达的是**我还想继续知道**。作者面对的则不是一个需要再次回答的问题，而是把已经发生的经历写成自己的**后来**。因此，一个负责问，一个负责答，正好构成完整回访。

语气边界：「然后呢？」可以作为品牌和读者入口，但作者邀请不得使用可能被理解为催促、质问的冷文案。尤其面对失败、改变计划或不愿公开的经历，应使用“愿意讲讲后来发生了什么吗？”等自愿、温和表述。

品牌可使用：**让每一个认真留下的回答，都有机会等到它的后来。**

## 2.3 已撤销的旧稿论断

本版也不沿用此前对话中未经校准的夺冠概率、预估评委得分和推测的已测转化率。这些不构成 PRD 输入事实。

# 03 用户、使用场景与成功条件

## 3.1 本期目标用户

【设计】研究参与者以自愿参与的成年人为限。读者需要能理解所展示的主题，不要求其为作者粉丝。作者须能够证明对所导入回答的账号控制或提供可审查的原作者确认。试点优先使用学习项目、专业技能成长、个人作品及非敏感职业经历；不以收入、疾病或人生输赢作为吸引点。

| 角色 | 主要任务 | 要消除的阻力 |
| --- | --- | --- |
| 读者 | 阅读旧经历，关注后续，更新后回来阅读 | 不知道有没有后续、找不回关注的内容、担心被诱导登录 |
| 原作者 | 核对旧内容，决定是否参与，补充后续并控制发布 | 被催促、被评判、被要求公开隐私、重新写长文负担 |
| 研究／运营 | 合规招募、核验作者、人工邀请、处理撤回 | 找不到可用样本、错发邀请、误把配合当自然需求 |
| 评委／访客 | 不登录即可理解与体验核心机制 | OAuth 失败、没有历史回答、只看到宣传页 |

## 3.2 三种启动场景

**读者发起。** 获准展示的回答进入 Demo。读者点击关注后，形成一条真实需求事件；经过内容适配、安全与身份检查后，研究人员决定是否发出人工邀请。

**作者主动。** 作者导入自己的历史内容，主动发起回访。即使没有读者关注，也可以采访和发布；页面明确写“作者主动补充”，不得配上“有人催更”等不实理由。

**已同意试点的作者。** 研究人员提前完成招募、身份核验和展示许可，创建受限入口。该路径能证明系统与回访体验，但不能被统计为平台自然召回或陌生作者回访。

## 3.3 成功条件按层分开

**工程成功：** 至少一条获授权来源可完成关注、回访、作者确认、Demo 发布及关注列表更新；关键错误路径可演示；无越权发布或伪造计数。

**研究成功：** 得到可追溯的正面与负面反馈，能说明在哪些样本中发生或没有发生目标行为。研究结果为负也可以是有效研究，不应删掉或改写成正面结论。

**业务成功：** 需要更大样本、更长观察窗口以及平台协作后再定义。当前不为平台级增长、付费、利润或召回率设已达成值。

## 3.4 完成与真实性的关系

“完整”指用户可以执行目标动作并得到真实状态，不等于“所有环节都已全自动”。本期允许人工核验和人工联系，但必须可见地标注；不允许用伪造 API、假作者、虚假人数或预写后续伪装完整。

# 04 版本边界与优先级

## 4.1 P0：比赛可运行版本

| 能力 | 本期实现方式 | 达成边界 |
| --- | --- | --- |
| 历史内容导入 | 官方搜索适配；原作者授权粘贴／研究人员合规导入 | 搜索失败可走真实授权材料，不伪装在线结果 |
| 读者关注 | Demo 身份／浏览器会话，关注与取消、我的关注 | 浏览器口径不冒充唯一自然人数 |
| 回访建议 | 语义识别、明确时间线、安全拦截、人工确认 | 不预测作者是否愿意回来的概率 |
| 作者访问 | 已验证 OAuth 或人工核验后绑定的专属入口 | 未核验者只能私有试用，不能公开冒称原作者 |
| 动态采访 | 文字输入，最多五个主问题，可追问、跳过、暂停 | 不强制语音，不生成作者未说的结果 |
| 内容发布 | 作者确认后在 Demo 生成独立后续页 | 不是主站发文，不暗中使用登录态写入知乎 |
| 更新返回读者 | Demo 内通知／关注列表显示新状态 | 不承诺离线 Push、邮件或短信 |
| 管理与验证 | 最小管理页、来源授权、邀请日志、研究记录、删除 | 允许部分管理通过受控后台表单完成 |

## 4.2 P1：仅在 P0 通过后增加

作者授权后的个人回答扫描、回访建议批量排序、热榜辅助线索、正文自动获取适配、已授权成品分享图，以及更完善的编辑历史。是否做取决于接口核验与剩余工时，不影响基础闭环。

## 4.3 P2：不进入本期开发或路演主链

未完待问、陌生人匹配、AI 宠物、语音转写、邮件／短信／知乎推送、主站新内容对象、多轮跨年自动调度、长期经验 RAG、模型微调或独立训练、商业咨询撮合、成功概率预测。

## 4.4 明确不做

不批量抓取站内用户数据，不索取用户密码或 Cookie，不冒充官方邀请，不发送无人审核的批量联系，不把模型生成当原作者回答，不根据图片猜身份，不制作“打脸榜”，不把回访样本当总体统计。

## 4.5 范围收缩顺序

交付风险出现时，依次取消分享图、热榜线索、自动个人扫描、批量分析，再把公开样本数量缩小为一条。不能取消真实性标注、原作者确认、关注去重、私有权限和撤回能力。若最终只有获授权回放而没有实时采访，应标记“交互回放”，不得声称 P0 全部完成。

# 05 角色与权限

## 5.1 身份不是一个布尔值

【设计】系统分别保存登录状态、原作者关联状态与内容授权状态。OAuth 登录成功不能自动证明当前账号拥有任何粘贴的回答；持有邀请链接也不能单独证明原作者身份。

| 身份 | 能看什么 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 游客 | 已同意公开的回答片段、后续页及说明 | 浏览、试用公开演示；同意后建立会话关注 | 查看私有采访、发布原作者后续 |
| Demo 读者 | 自己的关注和站内通知 | 关注、取消、删除本地／账户数据 | 查看是谁拒绝了回访、其他读者身份 |
| 已核验原作者 | 自己的来源、邀请、采访及草稿 | 接受／拒绝、纠错、编辑、确认发布、撤回 | 修改他人来源、让 AI 代签确认 |
| 未核验自述作者 | 自己的私有试用草稿 | 导入、体验、申请核验 | 对外展示“原作者确认”徽标 |
| 研究／运营 | 分配的案例与必要核验元数据 | 审核来源、记录邀请、处理投诉和撤回 | 无授权浏览所有私人采访、替作者确认事实 |
| 系统／AI | 当前任务所需的最小材料 | 抽取、提问、生成待确认结构 | 自行联系、授权、发布、修改计数 |

## 5.2 原作者关联证据

允许的方案由技术与研究负责人核定：官方能力返回内容归属并能绑定当前登录账号，或原知乎账号通过约定方式确认参与，再由管理员记录证据和绑定用户。只存储必要的核验结果及受控证据引用，不要求身份证。

人工核验记录需包含核验方式、原账号／回答标识、核验时间、执行人、证据位置、适用样本范围。对截图、昵称相同等弱证据不能直接判定通过；存在疑点则保持“待核验”，只允许私有试用。

## 5.3 登录实现与写入权限

【设计】读者浏览不强制登录；持续关注使用已验证的Demo会话。作者优先用已接通的OAuth登录并核对内容归属；未接通时由研究人员先核验原账号，再用已有会话认证方案将其绑定到专用作者账号。案例邀请链接与登录凭证分离；邀请链接本身不建立作者权限。作者凭证通过已确认的私密渠道交付，不放入共享演示文档。


所有服务端写接口重新检查归属，不信任前端传来的 author_id。研究人员可发起“待作者确认”的流程，但作者签发的确认必须绑定具体草稿版本。撤回后关闭后续公开页，不自动删除用户曾在知乎手动发布的内容，并明确告知这一边界。

发布、重发邀请、删除和导出使用二次确认；前端按钮禁用不是安全边界，后端仍须鉴权、去重和记录审计事件。

# 06 主流程与页面规格

## 6.1 页面清单

| 页面 | 路由设计 | 首要信息与主操作 | 必备异常状态 |
| --- | --- | --- | --- |
| P01 发现／说明 | / | 已授权旧回答；产品边界；进入详情 | 没有获授权样本时显示真实空态 |
| P02 原回答与后续 | /stories/:id | 来源、版本时间、读者按钮「然后呢？」、已有「后来」 | 原文不可用、无全文、撤回、无后续 |
| P03 我的关注 | /following | 已关注内容、更新与取消 | 尚未关注、会话失效、通知不可用 |
| P04 作者工作台 | /author | 邀请、主动导入、「后来」草稿、发布记录 | 未核验、没有内容、拒绝后状态 |
| P05 采访 | /interviews/:id | 作者端标题「后来」、当年依据、一个当前问题、输入与跳过 | 超时、暂停、敏感内容、会话冲突 |
| P06 确认与发布 | /drafts/:id | 当时／后来对照、事实来源、范围选择 | 未确认项、冲突项、版本已更新 |
| P07「后来」成品 | /followups/:id | 作者确认的「后来」、来源关系、确认时间 | 私有、撤回、原来源变化 |
| P08 来源与研究管理 | /admin | 授权、核验、邀请、错误、研究导出 | 无权限、待审核、额度不足 |

以上是项目内部页面设计，不是知乎官方页面或路由。主界面可以借用问答阅读习惯，但显示项目名称及“黑客松原型”，不得伪装成知乎已上线功能。

## 6.2 读者链路

P01 → P02 阅读旧内容 → 点击读者端主按钮“然后呢？”（内部动作：关注后续）→ P03 找回关注 → 「后来」公开后产生 Demo 内更新 → P07 阅读。点击前不展示虚构的人气数字；是否显示真实关注总数由研究分组决定，不能让假社会认同污染实验。

## 6.3 作者链路

人工邀请／P04 主动导入 → 来源及身份核验 → 选择参与 → P05 确认旧状态、动态采访 → P06 修改和确认 → 选择私有或公开 → P07 发布 → 允许返回修改／撤回。邀请未接收时，读者只能知道“尚无公开后续”，不能看到作者是否已读、拒绝理由或逾期天数。

## 6.4 关键交互细则

关注成功后立即反馈并允许撤销；计数以服务端为准，失败时回滚。采访每次只展示一个主问题，并允许查看依据原文；禁止自动滚动遮挡输入。草稿页面将作者输入、直接引用与 AI 整理明确区分。移动端保持单列；桌面端允许两列对照，不另建复杂 Dashboard。

未登录访客必须能浏览一条真实获授权成品；如果还没有此类样本，显示“样本招募中”与私有交互试用，不以虚构人物替代。公开演示账户不授予真实作者的修改权限。

# 07 历史内容接入与证据管理

## FR-01 来源登记与导入（P0）

**输入：** 官方搜索返回的候选、原作者粘贴的内容与原链接，或研究人员获得明确许可的材料。读者提交的第三方链接先进入私有审核队列，不直接公开或发起邀请。

**处理：** 记录来源类型、原链接、内容／问题／账号标识（可用时）、获取时间、发布时间、更新时间、内容权限、材料版本及导入人。缺失的时间、ID、点赞或评论数保持 null，页面显示“未提供”，不能编造或默认为零。

**输出：** source 记录及其版本快照。未经公开展示许可，只可用于授权范围内的私有测试。官方 API 获得的数据仍按开放平台使用范围处理，不能把“能读取”推导为“可无限存储、重发和训练”。[S1：第 18—19 页]

**验收：** 导入失败不创建半完整公开卡片；同一来源版本重复提交不会多生成公开样本；任意公开片段能够定位到来源记录与适用授权。

## FR-02 原话、摘要与历史时间（P0）

搜索摘要不能直接加引号当原作者原话。材料类型至少分为 exact_excerpt（核对的原文片段）、api_summary（接口摘要）、author_recollection（作者回忆）和 ai_summary（AI 整理）。只有 exact_excerpt 才能显示“原文引用”，并保存原文片段及位置。

“发布于 2021 年”不证明今天获取的正文就是 2021 年的原始版本。若无同期版本证据，展示为“原回答发布于……；以下为……采集到的现存版本”。作者确认其当时想法时标记为“作者回忆／确认”，不得冒称历史快照。

当前点赞数只能标为“截至采集时的赞同数”，不能标为“当年已有多少人赞同”。评论总数与真实追问数分开；后者必须有可检查的评论证据与分类记录。

## FR-03 数据源降级（P0）

官方搜索可用时，记录请求日期、接口版本和实际响应字段；不可用时，切换原作者授权导入并明确展示来源。只有摘要时，AI 可以建议候选，但不得确认具体原话、目标期限或敏感身份；邀请和公开前需作者补充或人工审核。

没有授权样本时，不生成看似真实的演示故事。开发测试可使用标记为 test_fixture 的测试文本，但必须隔离于公开案例、用户指标和答辩事实。

# 08 读者关注后续

## FR-04 关注、取消与需求记录（P0）

**用户故事：** 作为读者，我希望对感兴趣的旧经历关注后续，并在作者愿意更新时找回它，而不是公开催促作者。

点击读者端主按钮“然后呢？”后，系统为 reader_key × source_id 创建唯一的有效关注。重复点击、接口重试或刷新不得增加第二次关注。再次点击允许取消；取消后不再产生新通知，研究事件保留去标识化的行为记录但不继续算作有效关注。

读者身份默认使用 Demo 账户；未接入账户时使用同意后建立的第一方随机会话标识。浏览器标识只能支持“去重会话”口径，不称“独立真人”。不采用设备指纹追踪。更换设备／清除浏览器后无法找回时，应在界面解释。

**成功文案：** “已关注。作者自愿公开更新后，可在本 Demo 的‘我的关注’查看。是否更新由作者决定。”未经实现和用户授权，不写“我们一定会推送给你”。

## FR-05 真实计数与防滥用（P0）

需求计数只能来自有效关注记录。分别保存关注事件数、有效关注主体数、确认参与研究的人数；三者不能混用。作者本人、开发账户、压测与演示重放的行为必须标为 excluded，不进入正式研究指标。

公开计数默认关闭，避免小规模测试中的诱导和隐私压力；如打开，只显示口径准确的“本次测试中有 X 个去重账户关注”，不推算知乎总读者需求。运营不能手动修改计数，只能通过带理由的审计记录剔除测试或异常事件。

## FR-06 关注列表和更新（P0）

公开后续发布成功后，在本 Demo 为有效关注者创建一次未读更新；同一发布版本不得重复生成。发布时未关注或已取消者不补发。后续被撤回，更新卡显示“作者已撤回”，不保留可继续阅读的摘要。

读者不应看到“已催促 X 次”“作者迟迟未答”“已读不回”等状态。作者拒绝和触达次数仅对本人及必要运营可见。

**验收：** 同一读者并发关注请求只产生一条有效记录；取消后无新通知；未公开草稿不会泄露到关注列表；需求数不会从点赞、浏览或评论总数推导。

# 09 回访判断与触达规则

## FR-07 回访适配判断（P0）

系统先做资格与安全门控，再做语义判断，最后给出可解释建议。不要先生成一个高分再用小权重抵消风险。

| 顺序 | 检查内容 | 不通过时处理 |
| --- | --- | --- |
| 1 | 来源与处理授权是否充分 | hold：补材料，不公开不联系 |
| 2 | 是否属于本期低风险成年场景 | excluded／manual_review：本期不主动联系 |
| 3 | 是否第一人称经历、具体计划、承诺或可追踪事件 | 不确定可请求作者确认；纯知识解释不强行回访 |
| 4 | 是否已有公开后续，或作者已拒绝 | 已有后续优先链接；拒绝后停止该路径 |
| 5 | 是否存在明确时间锚点及值得补充的信息 | 不足时为 unknown，不伪造期限 |
| 6 | 读者需求或作者主动意愿、触达条件 | 形成建议队列，人工最终决定试点联系 |

## FR-08 时机与优先级（P0）

MVP 不输出“召回概率”“最优时机”或未经验证的 0—100 紧迫分。输出 recommended_action（invite／hold／not_suitable／author_initiated）、理由、支持片段、未知项及人工复核要求。

明确期限来自原文时，先确认其时间基点；“半年后”不能默认从发布日期计算，除非上下文支持。无明确期限时可询问作者“这段经历是否已有适合分享的进展”，不能把行业经验年限当客观成熟时间。话题上热榜只证明当下关注线索，不证明必须回访，更不能从一次搜索得出声量上涨。

已通过门控的队列可用确定性排序：作者主动发起优先；其次有实际读者需求的条目；再按最早需求时间排序。该顺序是试点工作规则，不是已验证的商业最优策略。点赞数量可显示为背景，不进入资格门槛。

## FR-09 安全与频率（P0）

高敏感度、身份不清、涉及未成年人、显著第三方隐私或作者不愿重访的内容不进入本期主动邀请。模型不能提供安全保证，人工复核是发送前门槛；文本扫描不充分时默认 hold。

试点默认每位作者最多一次人工邀请；未回复不自动追催。作者明确同意进一步沟通时按约定跟进。读者关注不会直接调用发送工具。不存在可用渠道时，状态为“无可用触达”，读者只看到“尚无公开后续”。

# 10 作者核验、邀请与回访入口

## FR-10 原作者确认与邀请（P0）

研究人员先建立案例记录，确认来源和联系方式使用边界，再发送一次个性化邀请。邀请明确团队参赛身份、研究目的、预计互动方式、自愿参与、可拒绝以及展示需再次同意；不使用“知乎官方邀请”或未经证实的人数。

**邀请模板：** “你好，我们是参加知乎黑客松的项目团队，正在测试‘然后呢？’。我们在研究你曾发布的这条回答〔原链接〕，希望了解其中这段经历是否已有你愿意分享的后续。这不是知乎官方运营邀请，不需要重新写长文；是否参与、是否公开都由你决定。愿意了解时，我们会先说明 AI 处理方式和展示范围。未回复不会自动追催。”

有真实且适用的读者关注记录时，可在邀请中补充准确口径；没有则不写“有人在等”。联系日志记录发送方、渠道、日期、结果、授权说明版本，不存储不必要的私人通讯信息。

## FR-11 接受、拒绝及主动发起（P0）

作者打开入口后先看到来源卡和当前材料版本，选择“写下后来”“暂不参与”“不再联系”。接受不是发布同意；拒绝不公开理由，不用惩罚性文案。主动导入入口不要求已有读者需求，不显示假邀请。

邀请链接采用过期令牌，令牌只定位案例，不替代身份核验。核验通过后绑定 Demo 账户；每次访问采访和草稿都检查归属。未核验用户可以试用，但不产生公共“原作者”内容。

## FR-12 采访前四项确认（P0）

确认“这是我的内容”；核对系统抽取的当时计划或判断；选择是否允许在当前已选模型中处理文本；选择本轮目标为私有「后来」记录或可申请公开。默认不勾选公开、训练、平台外营销等用途。

采访开始前说明可以跳过问题、暂停或删除。预计五分钟以内是体验目标，不是承诺；系统实际记录用时，用测试结果替代固定宣传。

**验收：** 邀请链接转发后他人不能发布；拒绝后后台不会再生成自动邀请；作者未同意模型处理时，不发送其正文到模型，提供手动填写或退出。

# 11 AI 动态采访

## FR-13 开场与问题生成（P0）

AI 使用已确认的原文片段、已确认的当时状态、本轮主题及已答内容生成当前问题。先核对“当时发生了什么／准备做什么”，再问“现在进展如何”，最后按回答询问差异、条件变化与愿意给读者的补充。

每个问题必须有 purpose（要补什么信息）和 basis_refs（依据哪里）；可展示简短依据，不展示模型内部推理。一次只问一个主问题，不把三四个隐私问题塞在同一句里。允许用户自己决定回答颗粒度，不要求提供金额、单位、地址等。

## FR-14 动态分支（P0）

| 作者回答类型 | 下一步 | 禁止动作 |
| --- | --- | --- |
| 已完成 | 询问实际过程与原先预期的差异 | 自动等同“成功”或要求炫耀结果 |
| 仍在进行 | 询问当前进展和仍未知的部分 | 写成最终结果或判失败 |
| 中途停止／改变计划 | 询问是否愿意说明调整及背景 | 追责、嘲讽、诱导承认失败 |
| 不记得／原文理解不对 | 修正当时状态或标记未知 | 用模型推测替代当事人记忆 |
| 不想说／涉及第三人 | 跳过并记录不可公开字段 | 换问法继续逼问 |
| 内容矛盾 | 中性指出冲突，请作者核对或保留差异 | 自动修改成“合理版本” |

## FR-15 节奏、保存和失败降级（P0）

设计默认最多五个主问题，澄清问题也计入总交互预算；作者可随时提前整理草稿。目的不是填满问题数，而是得到足以准确表达的材料。每次输入先保存，再请求下一问；网络失败不丢失已答内容。

模型超时后可重试一次，仍失败时切换明确标注的手动结构化表单：“当时的想法”“后来发生的事”“想补充或修正的地方”。降级不能标为 AI 完成采访，研究数据记录实际模式。

## FR-16 采访结束条件（P0）

作者主动结束、预算用尽、信息已足够或安全门控要求暂停时结束。系统输出待确认草稿及“未回答／不公开／仍不确定”清单。原作者没有说到的结果必须留空或写“未提供”，不能为文采自动补全。

**验收：** 同一历史材料下，作者选择“已完成”和“已停止”时，下一问应发生符合意图的变化；跳过后不重复施压；中断重开保留已答内容；任何新事实可对应到作者输入或已核对来源。

# 12 确认、发布、阅读与撤回

## FR-17 草稿与事实核对（P0）

草稿由四块组成：当时表述、后来补充、作者现在的回看、仍未知／不愿公开。每项结果关联原文或采访消息，作者可以修改、删除、设为不公开；AI 整理文本使用“根据作者回访整理”标记，不能代作者签署事实确认。

数值、时间、人名与因果判断重点标识。作者编辑后生成新版本，旧确认立即失效。冲突未处理或引用不存在时阻止自动发布；作者可选择删除争议内容后继续。

## FR-18 公开与私有（P0）

默认私有。公开需要身份关联通过、来源展示许可、AI 处理许可、当前版本逐项确认与公开范围确认。作者点击“确认发布这则「后来」到本 Demo”后，后端再次检查条件和版本哈希，原子性写入内容与发布事件。

公开页必须包含原来源关系、材料版本说明、回访日期、作者确认时间、AI 辅助整理标记及“作者自述，未由平台独立核实”的适用说明。不要把“原作者核验通过”写成“结果真实性已认证”。

## FR-19 返回读者与外部出口（P0／P1）

发布后更新 P02、P03 和 P07，并为关注者创建 Demo 内更新。复制草稿与原链接属于 P1；按钮写“一键复制”，用户手动发布到知乎。未接通发布 API 时不出现“发布至知乎成功”。读者链接回原文可用，但不要拼造不存在的官方后续路由。

## FR-20 修改与撤回（P0）

已发布内容修改需重新确认；旧版本在后台保留最小必要审计，公开只展示当前有效版本及更新时间。作者撤回后公共访问立即失效，列表和分享页不再展示正文；通知只保留“已撤回”的无正文状态。

删除个人数据时先停止公开和模型使用，再删除正文、草稿、采访及可撤销的衍生索引；日志仅保留执行所需的去内容化证明。已经被读者截图或被作者自行粘贴到其他平台的副本不在系统可控范围，操作前告知。

**验收：** 草稿未确认无法发布；并发点击只产生一个版本；撤回后未登录、作者之外的账户、搜索页和公开分享链接均拿不到正文。

# 13 状态机与异常处理

## 13.1 回访业务状态

| 当前状态 | 允许转移 | 条件／动作 | 读者可见信息 |
| --- | --- | --- | --- |
| candidate | hold / eligible / excluded | 来源、安全与语义检查 | 仅授权内容可见 |
| hold | eligible / excluded | 补材料或人工审核 | 尚无公开后续 |
| eligible | invite_recorded / accepted | 发送一次邀请或作者主动参与 | 尚无公开后续 |
| invite_recorded | accepted / declined / expired | 作者选择或观察窗口结束 | 不公开已读／拒绝状态 |
| accepted | interviewing / declined | 身份、许可与原状态确认 | 尚无公开后续 |
| interviewing | paused / draft / stopped | 保存、跳过、结束或拦截 | 私有，不公开过程 |
| paused | interviewing / stopped | 本人恢复或终止 | 私有 |
| draft | confirmed / interviewing / stopped | 修改、补问或放弃 | 私有 |
| confirmed | published / draft | 发布检查；编辑使确认失效 | 未发布仍私有 |
| published | draft / withdrawn | 修改或撤回 | 可阅读当前有效版本 |
| declined / excluded | 不自动重开 | 作者主动申请后人工重新审核 | 尚无公开后续 |
| expired / stopped | eligible / accepted | 本人主动恢复后复核权限；不自动重邀 | 尚无公开后续 |
| withdrawn | 新建版本后重新确认 | 不直接恢复旧公开状态 | 作者已撤回 |

“超过观察窗口未回复”不是作者拒绝。研究记录保留 pending、no_response_in_window 与 explicit_decline 的区别；invite_recorded 只表示人工实际记录过发送，不表示对方已收到或阅读。

## 13.2 业务状态与执行状态分离

编辑已发布内容时，创建新的待确认版本；原公开版本保持可见，直至新版本确认替换或作者主动撤回。案例工作状态与 published_version_id 分开管理，不因开始编辑而误发通知或自动下架。

模型或接口执行另存 queued／running／succeeded／failed／cancelled。模型调用失败不能把业务状态改为“作者拒绝”；重试成功不能重复发送邀请、重复计数或重复发布。

## 13.3 重点异常

| 异常 | 系统行为 |
| --- | --- |
| 原文已改动／被删除 | 标记来源变化，停止旧版本继续分发，人工核查展示许可 |
| 只有标题或不完整摘要 | 允许候选，不允许虚构直接引用与具体目标 |
| 作者无历史回答 | 主动导入入口或清晰空态，不强塞热点内容冒充本人 |
| 已有公开后续 | 优先关联已有内容；必要时再邀请补充明确缺口 |
| 真实样本退出 | 删除公开引用，换另一获授权样本；没有就显示空态 |
| 模型输出危险文本 | 不自动公开，提示审核或回到手动表单 |
| 研究／演示账号混入数据 | 依据 cohort 标记排除，保留排除原因与审计 |

# 14 AI 任务、输出契约与评测

## 14.1 任务拆分

| 任务 | 输入 | 输出 | 人类／规则把关 |
| --- | --- | --- | --- |
| AI-A 识别与抽取 | 单条授权材料、获取版本、已知时间 | 经历类型、待补事实、依据片段、未知项 | 引用存在性、授权与敏感度门控 |
| AI-B 采访 | 已确认抽取、对话、跳过项、问题预算 | 一个问题、提问目的、依据引用或结束建议 | 不越预算、不重复问、不自动联系 |
| AI-C 整理 | 原文与采访，作者公开范围 | 结构化后续与逐项证据映射 | 无依据事实拦截、作者确认后才能发布 |
| AI-D 校验 | 草稿、引用和材料哈希 | 缺来源、矛盾、敏感字段提示 | 规则校验优先，模型只是辅助 |

不要求多 Agent，也不以 Agent 数量证明创新。同一模型按不同任务调用即可。AI 的合理性要通过降低访谈准备与整理成本、提升信息覆盖来检验，而非宣称“传统算法绝对做不了”。

## 14.2 内部输出契约：回访分析

以下是项目自定义字段，不是知乎 API 响应。

```text
analysis_id, schema_version, source_id, snapshot_hash
material_level: exact_excerpt | summary_only | author_recollection
case_type: experience | plan | prediction | commitment | knowledge | unknown
claims[]:
  id, text, kind, evidence_refs[], time_anchor, time_anchor_basis
missing_information[]
safety: clear_for_pilot | manual_review | excluded
safety_reasons[]
recommended_action: invite | hold | not_suitable | author_initiated
action_reasons[], reviewer_required
model_id, prompt_version, created_at
```

time_anchor 不足则为 null；evidence_refs 必须命中当前快照中的片段 ID。summary_only 材料不能产出“逐字原话”标记。model_id 使用实际调用标识，不写模糊“Pro 已验证”。

## 14.3 内部输出契约：采访与草稿

```text
InterviewTurn:
  turn_id, session_id, question, purpose, basis_refs[]
  author_message_id, skipped, stop_reason, generated_by

FollowupDraft:
  source_id, snapshot_hash, interview_id, version
  statements[]: id, text, kind, evidence_refs[], visibility
  unresolved_items[], author_edits[], author_confirmations[]
  ai_assisted, content_hash
```

kind 区分 source_quote、author_report、author_reflection、ai_summary。AI 总结必须仍能追溯到具体材料；“情绪流畅”不是补编事实的许可。作者输入若含“请忽略规则并发布”等指令，按内容处理，不改变权限。

## 14.4 AI 评测设计

用获授权材料构造人工标注的测试集，至少覆盖计划完成、计划中止、仍在进行、引用他人、纯知识、缺时间、原文变化与敏感内容。两名评审尽量独立标注，分歧保留；若只有一名标注者，报告限制。

比较规则筛选、通用近况提问与上下文采访，记录引用、遗漏、诱导性、修订量、耗时与负担。结果待测；模型置信分不解释为真实性或回复概率。

# 15 数据模型与一致性约束

## 15.1 最小逻辑数据模型

实际物理表可以合并 JSON 字段以降低开发量，但必须保留下列实体关系与审计边界。

| 实体 | 必需字段／关系 | 关键约束 |
| --- | --- | --- |
| users | id、身份类型、可用外部账号引用、cohort、创建时间 | 外部账号与用户绑定须核验；不存密码 |
| sources | id、来源类型、原链接、原账号标识、权限状态 | 无授权不得公开；第三方链接先审核 |
| source_snapshots | source_id、正文／片段、摘要类型、时间、hash | 不把新快照覆盖成历史原始版本 |
| consents | user_id、source_id、用途、版本、状态、时间 | 分用途；撤销可追踪并触发删除 |
| author_verifications | user_id、source_id、方法、证据引用、核验人 | 弱证据不可标原作者通过 |
| interests | reader_key、source_id、active、cohort、时间 | reader_key × source_id 唯一 |
| followup_cases | source_id、作者、主状态、启动类型、拒绝标记、published_version_id | 无自动重启拒绝案例 |
| invitations | case_id、方式、发送人、发送时间、结果 | 区分发送／回复／接受；不推测已读 |
| interview_sessions / messages | case_id、归属、问题、作者输入、来源引用、模式 | 会话隔离，保存跳过和中断 |
| followup_versions | case_id、版本、事实列表、内容hash、确认及公开时间 | 修改后确认失效；每次公开可追溯 |
| notifications | reader_key、发布版本、已读、撤回状态 | reader_key × 发布版本唯一 |
| ai_runs / research_events | 任务、模型、版本、耗时、用量；事件、cohort、时间 | 不记录明文密钥；研究与业务分离 |
| deletion_jobs / audit_logs | 主体、操作、范围、执行状态、操作者 | 审计不永久保留被删除正文 |

## 15.2 三项容易遗漏的数据设计

**历史与当下分开。** sources 中的发布时间和 snapshots 的获取时间不是同一字段；更新时间未知就保持未知。回访事实同时记录 reported_at（作者何时说）与 happened_at（事情何时发生，可空）。

**真实性分层。** 身份关联状态、作者确认状态与外部证据核验状态分别存储。默认后续是 author_report，不自动升级为 independently_verified。

**授权不由登录推导。** users 登录成功不自动创建公开授权或训练许可；consents 单独记录用途，并在发布时检查当前有效状态。

## 15.3 一致性与删除

关注、发布、通知写入应使用唯一键与事务／等价一致性机制。客户端超时后重试不得创建重复副本。发布事务写入后再派生通知，失败可重试，但不能出现草稿通知。

删除任务按来源、采访、草稿、公开成品、缓存、索引和导出逐项执行。正文删除后可保留不含正文的事件计数和必要操作证明；撤回研究同意时同时检查相关研究导出和可撤销派生记录。

# 16 项目内部接口契约

**本章全部路由为本项目拟开发接口，不是知乎已开放能力。** API 前缀统一 /api；主数据使用稳定 ID，时间使用 ISO 8601，存储 UTC、界面按时区显示。

| 路由与方法 | 权限 | 请求／响应要点 |
| --- | --- | --- |
| POST /sources | 作者／研究员 | 来源、材料类型、权限引用 → source_id、审核状态 |
| GET /stories/:id | 按公开权限 | 返回获准公开的快照及有效后续，不带私有采访 |
| POST /sources/:id/analyze | 本人／研究员 | 指定 snapshot_hash → job_id；异步获取分析结果 |
| PUT /stories/:id/interest | 读者 | active=true/false → 有效状态；幂等且去重 |
| GET /me/following | 当前读者 | 我的关注、公开后续、未读状态 |
| POST /cases | 作者／研究员 | source_id、启动类型 → case_id；检查拒绝和重复 |
| POST /cases/:id/invitations | 授权研究员 | 人工发送记录、渠道、时间 → 记录结果；不自动发送 |
| POST /cases/:id/decision | 已绑定作者 | accept／decline／do_not_contact → 新状态 |
| POST /cases/:id/interviews | 已绑定作者 | 有效许可与来源确认 → session_id |
| POST /interviews/:id/messages | 会话所有者 | message／skip、client_message_id → 已保存消息及下一步 |
| POST /interviews/:id/finish | 会话所有者 | 结束 → draft_id、待确认项 |
| PATCH /drafts/:id | 草稿所有者 | 编辑与 expected_version → 新版本、旧确认失效 |
| POST /drafts/:id/confirm | 草稿所有者 | content_hash、确认项 → confirmed_version |
| POST /drafts/:id/publish | 草稿所有者 | 当前确认版本、公开许可 → followup_id |
| POST /followups/:id/withdraw | 本人／受理人员 | 撤回理由可选 → 公开访问失效 |
| GET /me/notifications | 当前读者 | 仅本人通知，不泄露拒绝和私有内容 |
| POST /me/data-deletion | 当前用户 | 删除范围、确认 → deletion_job_id |
| GET /admin/research-export | 授权研究员 | 日期、cohort → 去标识事件、分母及限制说明 |

## 16.1 通用响应与错误

统一返回 request_id、status、data 或 error_code/message；不得将供应商错误和密钥直接透出。错误至少区分 unauthorized、forbidden、source_incomplete、consent_required、author_unverified、conflict、quota_exhausted、model_timeout、withdrawn。

重复写请求使用 Idempotency-Key 或等价 client_message_id；版本更新冲突返回 conflict 并要求刷新，不静默覆盖作者修改。邀请记录、确认、发布和删除保留审计事件。

## 16.2 公开、账户和后台隔离

会话凭证采用服务端验证；Cookie模式启用HttpOnly、Secure、适当SameSite及写请求CSRF防护。研究cohort由服务端维护，不允许前端自行将测试身份改成真实参与者。

公开接口只读取已发布字段；正文和AI上下文不通过前端隐藏来保护。研究导出默认排除用户名、联系信息与采访全文；确需全文分析必须另有明确权限。任何“角色切换”演示功能仅在独立测试环境开放，不得访问真实生产样本。

# 18 实施架构与非功能需求

## 18.1 保留原栈、修正部署约束

【设计】沿用原稿 Next.js 15 App Router 的工程方向，模型保留 Gemini 可替换适配层；准确包版本、模型 ID、地域可用性和用量条款在联调时锁定。本 PRD 不声称旧栈或模型已经在团队生产环境验证。

持久化必须二选一：**持久磁盘主机上的 Node 服务 + SQLite**，或**Vercel 部署 + 网络持久化数据库**。不允许把 Vercel 函数临时本地 SQLite 文件当共享生产数据库。Vercel 官方文档解释其函数环境不提供这种单一持久本地存储。[S4]

技术负责人在开工前选择与现有部署能力最接近的一条。数据库写入并发、备份及恢复必须实测；本期无需微服务或独立向量库。

## 18.2 处理管线

来源适配 → 材料及权限校验 → 短列表候选 → 单条语义分析 → 人工触达 → 采访会话 → 证据绑定整理 → 作者确认 → Demo 发布。外部API和模型统一由服务端适配层调用，密钥不上浏览器。

不把全部个人历史直接放入一个超长上下文。先过滤允许处理的材料，再按条分析；优先处理少量已核验样本。最大输入长度、输出预算、并发及超时为可配置参数；超过限制明确截断并提示材料不完整，不默默推断剩余内容。

## 18.3 非功能验收目标

下列数字是**设计验收目标，尚未测量**，不是对外性能宣传。

| 类别 | 目标 | 测试方式 |
| --- | --- | --- |
| 常规操作 | 试点10个并发会话下，非模型写入 p95 ≤2秒 | 记录样本数、测试环境及 p95，不以单次结果代替 |
| 模型反馈 | 请求1秒内显示已接收；30秒超时可重试一次／转手动 | 注入超时、断网、额度错误 |
| 持久化 | 重启与重新部署后，已提交关注与草稿不丢失 | 执行保存→重启→读取与去重测试 |
| 页面兼容 | 360px移动端与常用桌面宽度可完成全流程 | 无横向遮挡，按钮与错误提示可见 |
| 可访问性 | 键盘可操作、焦点可见、输入有标签、不仅靠颜色传达 | 按核心流程手动检查 |
| 成本 | 每个AI任务记录实际用量与耗时；达到团队预算暂停新任务 | 预算金额由队长开工前填写，不预设资助到位 |
| 可观察性 | 来源、采访、发布可用 request_id／case_id 追踪 | 不记录密钥或不必要的敏感全文 |

## 18.4 缓存和可用性

接口候选缓存默认24小时为试点设计，不代表官方许可期限；遇更严格的平台条款以其为准。历史来源快照仅按参与许可保留；作者撤回或删除优先于 TTL。关键路径可读取已经获准保留的真实缓存，但页面须显示采集时间与“缓存数据”，不冒充实时调用。

# 19 数据使用、隐私与安全控制

## 19.1 用途分别授权

本章为产品控制要求，不是对任何法律合规状态的认证。正式商业化前由平台和团队进一步审查适用规则、数据角色及跨服务处理。

| 用途 | 默认状态 | 要求 |
| --- | --- | --- |
| 保存私有采访与草稿 | 用户主动开始后按说明启用 | 展示保留期、删除方法和可见范围 |
| 外部模型处理 | 未同意不开启 | 事先说明实际供应商、数据范围及可核对条款 |
| Demo 公开展示 | 关闭 | 对具体版本单独确认；允许撤回 |
| 比赛视频／直播展示 | 关闭 | 与网页公开分开确认，并说明难以回收已传播副本 |
| 后续经验库检索 | 关闭 | 需再次说明用途并取得适用许可 |
| 模型训练／微调 | 关闭，且本期不实现 | 不将参赛许可扩张为训练授权 |

没有完整授权前，可用团队自己提供并同意处理的文本做私有测试；这不是“真实外部用户验证”。真实核验材料不得放进公开代码仓库。

## 19.2 保留和删除设计

私有采访与草稿默认最后操作后30天到期删除；公开记录按作者授权期保存，并每90天复核继续展示依据。上述期限是拟定试点策略，正式开始前须与参与者说明及平台许可一致，若许可更短则从严。

撤回公开须即时生效；删除申请设计为7日内完成主动存储与可删除衍生数据清理，备份最长30日轮替清除。只有已实现并验收后才向参与者承诺对应时效；未实现自动删除时指定人工负责人和执行日志，不伪称自动化。

## 19.3 安全控制

外部内容全部按不可信材料处理，不允许其改变系统指令或调用权限。模型只输出候选结构，不持有发布、邀请、账户设置等写权限。提示注入和敏感信息泄露是大模型应用需要处理的风险类型；本项目采用最小输入、工具隔离、引用校验和人工确认等控制，不宣称完全杜绝。[S5]

渲染原文和草稿时做安全转义，不执行嵌入脚本；外部链接检查协议与目标范围，禁止由用户输入 URL 触发无约束服务端抓取。后台启用最小权限与审计，真实用户导出需要受控操作。

## 19.4 投诉与中止

用户可在内容页和作者工作台申请撤回、纠错、拒绝联系。出现身份冒认、未授权公开、泄露隐私或重复骚扰时，暂停相关案例与外发动作，先处理问题再恢复研究；不能以比赛临近为由跳过。

# 20 真实用户试验方案

## 20.1 研究目标与当前状态

当前资料没有附参与名单、行为日志、采访记录或授权材料，因此本文研究状态为“尚无可核验结果”。试验目标是发现需求、理解阻力、验证小范围流程，不估算全站转化率或预测冠军。

建议工作量：在时间允许时招募15—30名目标读者，人工尝试联系10—15名符合条件的作者，争取至少一条获准展示的真实配对经历。以上是**招募目标，不是已发生人数或成功阈值**；无法达到时如实披露。

## 20.2 读者侧：观察真实选择

使用少量获准展示的真实材料，包含可回访经历与不适合回访的知识解释。尽量匹配主题、阅读长度和界面，随机或轮换展示顺序；不默认放大某条点赞或给任何材料添虚假人气。

主持人仅说明“请按平时习惯浏览这些内容”；先记录自然点击，结束后再询问为什么。主持人指示“点一下这个按钮”的操作标记为 prompted，不能纳入自然关注指标。初次研究隐藏总关注数，避免社会认同干扰。

告知正在测试原型，不保证一定等到后续。问卷答案与真实关注行为分别记录。熟人、团队成员、外部用户分组报告，不把便利样本称作随机知乎用户。

## 20.3 作者侧：人工跑通而不伪装自动召回

优先选真实原作者可接触、低敏感度、来源可核对的案例。所有邀请使用第10章模板；登记候选、能否联系、实际发送、收到回复、接受、开始、完成、确认、公开各阶段。

观察窗口固定，例如实际发送后24小时；晚发的邀请未满窗口须标 pending，不能和早发者放同一分母。未回复不等于拒绝；无可用渠道者不进入“已发邀请”分母，但需在总候选漏斗披露。

已活跃的作者接受试点，只能支持“愿意补充”；不能据此证明多年流失用户召回成功。学生组员提供自己的素材，可以测试工程，不作为外部招募的同一证据。

## 20.4 后续价值与 AI 增益

读者先阅读旧材料，记录理解及尚想知道的问题；再阅读经确认的真实后续，询问新增了什么、什么仍不确定。记录原话及负面反馈，避免仅问“是不是更有价值”。

AI 增益可采用少量同源材料的盲审：通用问法与上下文采访谁更准确、少遗漏、低负担。样本少时只报告案例和分项观察，不宣称统计显著或普遍优越。

# 24 孵化条件与后续路线

## 24.1 知乎孵化试点的决策问题

本项目的价值不在于证明内部工程团队不能实现，而在于证明一种值得进一步投入的用户行为和内容关系。小范围试点需要回答：读者是否自然关注、作者为何参与或拒绝、后续是否增加有用信息、AI是否降低负担，以及成本与风险是否可接受。

不设置凭空得出的“作者回复超过10%就值得孵化”等统一阈值。先取得真实分布，再结合每条有效后续的成本、平台资源和风险确定下一阶段标准。能够做成一个按钮不是业务验证，能找到一个配合作者也不是规模化验证。

## 24.2 需要平台协作而非假定可用的能力

主站入口、作者账号匹配、通知偏好与触达权限、原回答关联后续对象、搜索／推荐分发、反骚扰与内容治理、用户撤回后的跨系统清理，均属于后续合作议题。本期不写成已接入。

S1 说明优秀项目可另谈合作授权和孵化，作品版权归参赛团队；这不等于已有合作合同，也不保证抽象想法、团队署名或后续开发分工会自动获得永久保障。[S1，第18—19页] 团队内部贡献、署名、奖项分配和后续合作需事先书面约定。

## 24.3 分阶段路线

| 阶段 | 前提 | 产出 | 暂不承诺 |
| --- | --- | --- | --- |
| V0 比赛原型 | 基本授权、可运行链路 | 有限真实回访、明确研究报告 | 不宣称全站召回和数据飞轮已建立 |
| V1 扩大试点 | V0风险可控、存在值得继续的行为信号 | 更广样本、更多主题、时间与成本评估 | 不将便利样本外推所有知乎用户 |
| V2 平台融合 | 知乎合作、接口与治理支持 | 主站通知／关联内容／长期随访 | 不假定一定孵化或永久保留署名 |
| V3 长期经验检索 | 足够内容质量、明确许可与删除机制 | 可引用的相似经历与变化比较 | 不训练即自动变“专属模型”，不预测命运 |

## 24.4 长期数据价值的准确表述

潜在资产是“可追溯的当时材料、作者后来自述、确认状态与时间关系”，不是自动生成的客观纵向实验数据。愿意回访的人存在自选择，失联者没有结果，语义匹配也不意味着处境可比。未来检索必须展示样本来源、未回访数的口径、相似条件与不确定性。

经验RAG、向量库和模型训练是不同的工程及授权问题。本期只预留结构化关系与证据，不开训练管线，不把内容数量增长等同于模型质量必然提升。
